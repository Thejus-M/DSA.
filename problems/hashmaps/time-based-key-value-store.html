Time Based Key-Value Store

MEDIUM HASH MAP BINARY SEARCH DESIGN
PROB:

Design a time-based key-value data structure that can store multiple values for the same key at different time stamps and retrieve the key's value at a certain timestamp.

Implement the TimeMap class:

  • TimeMap() Initializes the object of the data structure.
  • set(String key, String value, int timestamp) Stores the key `key` with the value `value` at the given time `timestamp`.
  • get(String key, int timestamp) Returns a value such that set was called previously, with timestamp_prev <= timestamp. If there are multiple, it returns the value associated with the largest timestamp. If there are no values, it returns "".
CONST:
  • 1 <= key.length, value.length <= 100
  • 1 <= timestamp <= 10^7
  • All the timestamps of set are strictly increasing.
  • At most 2 * 10^5 calls will be made in total.
EXAMPLE:
  • •
    INPUT
    set("foo", "bar", 1)
    get("foo", 1) => "bar"
    get("foo", 3) => "bar" (closes timestamp <= 3)
    set("foo", "bar2", 4)
    get("foo", 4) => "bar2"
    get("foo", 5) => "bar2"

The Question

Imagine you have an object like a dictionary, but every time you update a key, the internal system remembers its previous values and when they were updated! This is heavily utilized in history states and backend transaction rollback logs. We need to rapidly push new timestamps, and rapidly query the most fitting timeline state in logarithmic time.

Intuition

To solve this, we can bridge two incredibly powerful concepts: Hash Maps (for instant $O(1)$ key lookups) and Binary Search (for rapid $O(\log n)$ historical timeline lookups).

Phase 1: Storage Architecture

Because problem constraints state that all `set()` timestamps are strictly increasing, any list we append updates into will automatically be perfectly sorted!

Phase 2: Timeline Queries

Using Binary Search, we can instantly dive into the Hash Map array and pinpoint the largest valid timestamp boundary under $O(\log n)$ limits.

Solution

Python Solution 
from collections import defaultdict

class TimeMap:

    def __init__(self):
        # Store key -> list of [value, timestamp]
        self.store = defaultdict(list)

    def set(self, key: str, value: str, timestamp: int) -> None:
        # Since timestamps are increasing, the list remains perfectly sorted automatically.
        self.store[key].append([value, timestamp])

    def get(self, key: str, timestamp: int) -> str:
        res = ""
        arr = self.store.get(key, [])

        # Binary Search to find the largest historically valid timestamp
        left, right = 0, len(arr) - 1
        while left <= right:
            mid = (left + right) // 2
            
            # Exact match!
            if arr[mid][1] == timestamp:
                return arr[mid][0]
                
            # Valid history timestamp, record it and try to get closer
            if arr[mid][1] <= timestamp:
                res = arr[mid][0]
                left = mid + 1
            # Too far into the future, cull the right boundary
            else:
                right = mid - 1
                
        return res

Complexity Analysis

Time Complexity
O(1) set, O(log n) get
Appends are instant. Queries slice search space.
Space Complexity
O(n)
HashMap utilizes memory relative to set() events.
