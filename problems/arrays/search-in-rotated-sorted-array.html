Search in Rotated Sorted Array

MEDIUM ARRAY BINARY SEARCH
PROB:

There is an integer array nums sorted in ascending order (with distinct values).

Prior to being passed to your function, nums is possibly rotated at an unknown pivot index k (1 <= k < nums.length) such that the resulting array is [nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]] (0-indexed).

Given the array nums after the possible rotation and an integer target, return the index of target if it is in nums, or -1 if it is not in nums.

You must write an algorithm with O(log n) runtime complexity.

CONST:
  • 1 <= nums.length <= 5000
  • -10^4 <= nums[i] <= 10^4
  • All values of nums are distinct.
  • nums is an ascending array that is possibly rotated.
  • -10^4 <= target <= 10^4
EXAMPLE:
  • •
    INPUT
    nums = [4,5,6,7,0,1,2], target = 0
    OUTPUT
    4
    0 is found at index 4.
  • •
    INPUT
    nums = [4,5,6,7,0,1,2], target = 3
    OUTPUT
    -1
    3 does not exist in the array.

The Question

Searching through a sorted array in O(log n) time usually requires a simple binary search. However, what happens when that sorted array has been rotated? A rotated array consists of two individually sorted subarrays. We need to adapt the classic algorithm to identify which half of the array is properly sorted, and whether our target lives in that half.

Intuition

Let's walk through the core logic of adapting Binary Search for a rotated environment across two phases.

Phase 1: Finding the Sorted Half

Because the array is rotated, dividing it exactly in half will always yield at least one side that is completely sorted. If nums[left] <= nums[mid], the left side is sorted. Otherwise, the right side is sorted!

Phase 2: Narrowing the Bounds

Once we establish which side is sorted, we test if the target easily fits inside that boundary. If it does, we discard the other half! If it doesn't, we're forced to search the jagged, rotated half.

Solution

Python Solution 
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums) - 1
        
        while left <= right:
            mid = (left + right) // 2
            
            if nums[mid] == target:
                return mid
            
            # Check if the left half is rigidly sorted
            if nums[left] <= nums[mid]:
                # Is the target inside this sorted half?
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1
            # Otherwise, the right half MUST be sorted
            else:
                # Is the target inside the right sorted half?
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1
                    
        return -1

Complexity Analysis

Time Complexity
O(log n)
Search space is repeatedly halved at every step.
Space Complexity
O(1)
Only constant memory is used for indices.
